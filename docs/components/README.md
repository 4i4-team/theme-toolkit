# Components (Composition) Subsystem

Composes recipes from multiple primary subsystems (colors, typography, layout, effects) into unified component class names. Instead of duplicating CSS, it references existing subsystem recipe classes and only generates a delta class for additional CSS overrides.

**Files:** `src/subsystems/components/` — `index.ts`, `types.ts`, `recipes.ts`, `theme.ts`.

---

## Raw input

Components lives under `rawTheme.components`. It has a single reserved key: `recipes`.

```ts
createTheme({
  breakpoints: { sm: 576, md: 768, lg: 1024 },
  colors: {
    primary: { base: "#4dabf7", text: "#fff" },
    recipes: {
      solid: { primary: { background: "primary", color: "primary.text" } },
    },
  },
  typography: {
    fontFamily: { base: "system-ui", variants: { heading: "Georgia, serif" } },
    fontSize: { base: 16, variants: { lg: 20 } },
    recipes: {
      heading: { large: { fontFamily: "heading", fontSize: "lg" } },
    },
  },
  effects: {
    radius: { base: 4, variants: { lg: 8 } },
    shadow: { base: "0 1px 3px rgba(0,0,0,.12)", variants: { lg: "0 10px 15px rgba(0,0,0,.1)" } },
    recipes: {
      card: { elevated: { borderRadius: "lg", boxShadow: "lg" } },
    },
  },
  components: {
    recipes: {
      buttons: {
        primary: {
          colors: "solid.primary",
          typography: "heading.large",
          effects: "card.elevated",
          css: { cursor: "pointer", border: "none", padding: "12px 24px" },
        },
      },
      cards: {
        elevated: {
          effects: "card.elevated",
          css: { background: "#fff", overflow: "hidden", padding: "16px" },
        },
      },
    },
  },
}, { components: { prefix: "brand", classPrefix: "brand-comp" } });
```

---

## Recipe props

Each recipe variant can reference recipes from four primary subsystems plus provide inline CSS overrides:

| Prop | Type | Description |
|---|---|---|
| `colors` | `string` | Reference to a colors recipe: `"group.variant"` |
| `typography` | `string` | Reference to a typography recipe: `"group.variant"` |
| `layout` | `string` | Reference to a layout recipe: `"group.variant"` |
| `effects` | `string` | Reference to an effects recipe: `"group.variant"` |
| `css` | `Record<string, string \| number>` | Inline CSS overrides (camelCase or kebab-case) |

### Reference format

Subsystem references use dot-notation: `"group.variant"` where `group` is the recipe group name and `variant` is the variant name within that group. The reference resolves to the class name generated by the primary subsystem's recipe pipeline.

Example: `colors: "solid.primary"` resolves to the class name `dt-color-solid-primary` (or whatever the colors subsystem's classPrefix generates).

### CSS overrides

The `css` prop contains raw CSS property-value pairs. These are emitted as a delta class — a separate CSS rule that only contains the overrides not covered by referenced subsystem recipes.

Property names can be camelCase (`borderRadius`) or kebab-case (`border-radius`). CamelCase is automatically converted.

## Output shape

```ts
theme.components.recipes         // raw passthrough
theme.components.nodes           // CssRuleNode[] (delta classes only)
theme.components.classes         // { group: { variant: ResolvedComponentClass } }
theme.components.getClass(g, v)  // combined className string
```

### ResolvedComponentClass

Each entry in `classes` is a `ResolvedComponentClass`:

```ts
{
  classes: string[];    // [referenced-class-1, referenced-class-2, delta-class]
  className: string;    // "referenced-class-1 referenced-class-2 delta-class"
}
```

- `classes` — array of all class names (referenced + delta)
- `className` — space-joined string, ready to use in `class="..."` attributes

### getClass()

`theme.components.getClass("buttons", "primary")` returns the `className` string directly:

```
"dt-color-solid-primary dt-type-heading-large brand-fx-card-elevated brand-comp-buttons-primary"
```

---

## How composition works

1. **Reference resolution** — for each subsystem key (`colors`, `typography`, `layout`, `effects`), the `"group.variant"` string is looked up in that subsystem's generated classes. If found, the class name is added to the component's class list.

2. **Delta class generation** — the `css:` overrides go through the recipe pipeline's `interpretRecipe` hook, producing a `CssRuleNode` with only those declarations. The delta class name follows the components subsystem's classPrefix pattern.

3. **Combined output** — the final `className` is all referenced classes plus the delta class, space-joined. Apply this single string to your element and all composed styles apply.

```html
<!-- All four subsystems' recipe styles + custom overrides in one class attribute -->
<button class="dt-color-solid-primary dt-type-heading-large brand-fx-card-elevated brand-comp-buttons-primary">
  Primary Button
</button>
```

---

## CSS output

The components subsystem generates minimal CSS — only the delta classes:

```css
.brand-comp-buttons-primary {
  cursor: pointer;
  border: none;
  padding: 12px 24px;
}

.brand-comp-cards-elevated {
  background: #fff;
  overflow: hidden;
  padding: 16px;
}
```

The referenced subsystem classes (`.dt-color-solid-primary`, `.brand-fx-card-elevated`, etc.) are already generated by their respective subsystems and included in `theme.css`.

---

## Options

| Option | Type | Default | Description |
|---|---|---|---|
| `prefix` | `string` | `"dt"` | CSS variable prefix (unused for components, but passed through). |
| `classPrefix` | `string` | `"dt-comp"` | Delta class name prefix. |

---

## Helper hooks

| Hook | What it does |
|---|---|
| `interpretRecipe` | Extracts `css:` overrides and converts to CSS declarations for the delta class. |
| `dependsOn` | Declares dependency on `["colors", "typography", "layout", "effects"]` to ensure primary subsystems are built first. |

---

## Dependencies

The components subsystem depends on all four primary subsystems. It runs after them so that recipe class names from colors, typography, layout, and effects are available for reference resolution.

If a referenced recipe doesn't exist (e.g., `colors: "solid.missing"`), the reference is silently skipped — no class is added for that subsystem. The delta class and other valid references still work.
